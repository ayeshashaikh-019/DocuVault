# Security Notes

This is an academic local-development build, not a certified production system. Current controls in the project:

- Passwords are stored as bcrypt hashes, never as readable passwords.
- Session IDs are stored server-side in SQLite; the cookie is HTTP-only and SameSite=Lax.
- The session secret is environment-based and `.env` is excluded from Git.
- Mutating API requests require a session-bound CSRF token in `X-CSRF-Token`.
- Login and registration attempts are rate-limited.
- Helmet supplies security headers and a restrictive Content Security Policy.
- User-provided text is rendered with HTML escaping in the browser.
- Database operations use prepared statements.
- Uploads are size-limited and restricted by extension/MIME type and basic file signature checks.
- Stored filenames are generated by the server; original filenames are display metadata only.
- Uploaded documents live outside the public static directory and are delivered only through an authenticated, permission-checked route.
- Restricted file access and other denied operations are recorded in the activity log.

## Before a real deployment

1. Change or remove all demo accounts and passwords.
2. Set `NODE_ENV=production` and a unique random `SESSION_SECRET` of at least 32 characters.
3. Serve over HTTPS and set `TRUST_PROXY=1` only when running behind a trusted reverse proxy.
4. Run `npm audit` and update dependencies deliberately; keep a lockfile under version control after dependency installation.
5. Add regular database and private-file backups, restoration testing, and retention policy.
6. Add malware scanning and stronger file-content inspection appropriate to the institution.
7. Add monitoring, security logging, account recovery, password reset, and administrative review processes.
8. Perform a security assessment and verify applicable institutional data-protection requirements.
